# Product — Spec Template

Copy this into a doc before building anything user-facing. Keep it to two pages.

## 1. Problem
Who has this problem, and when? What does it cost them today? One paragraph, specific.

## 2. Why now
What changed that makes this worth doing this quarter?

## 3. Goals / Non-goals
- **Goals:** the outcomes this must achieve.
- **Non-goals:** what we're explicitly *not* doing (this is where scope creep dies).

## 4. Success metrics
The one number that tells us it worked, plus a guardrail metric that tells us we didn't break something.

## 5. Proposal
The smallest version that tests the core bet. What the user sees and does.

## 6. Open questions
What we don't know yet and how we'll resolve it.

> A spec that can't name what it's *not* doing isn't ready.
